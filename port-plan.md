# Ограничения пилота и план переноса

## Что в пилоте не закрыто

**Безопасность ролей.** Правила базы на платформе задаются по путям и уровням доступа к артефакту, а не по ролям внутри ЖК. Поэтому любой участник артефакта может записывать в общие коллекции, а проверки «это председатель», «это автор» выполняет интерфейс. Защищены на уровне базы только голоса, отметки участия и личные данные: каждый пишет лишь в свою запись.

**Приватность.** Любой участник технически может прочитать все общие данные ЖК, включая личные сообщения, номера квартир и машин. Интерфейс их не показывает, но база не запрещает. Поэтому пилот подходит для команды и доверенных жителей, а не для публичного запуска.

**Коды подъездов.** Шестизначный код хранится отпечатком, но перебрать миллион вариантов отпечатка возможно, а ограничение попыток работает только в интерфейсе.

**Аккаунты.** Пользователи — это аккаунты claude.ai. Жители извне организации могут только смотреть.

**Деньги.** Эквайринга нет: житель отмечает «Я оплатил», поступление подтверждает ОСИ или Тредо.

**Уведомления и устройства.** Нет пушей и SMS (только колокольчик в приложении), нет виджетов экрана блокировки, домофон, шлагбаум и камеры не подключены.

## Целевой стек

| Часть | Технология | Что переносится из пилота |
| --- | --- | --- |
| Мобильное приложение жителя | Expo (React Native), TypeScript | экраны `S`, токены из `01-design-system.css`, тексты |
| Кабинет ОСИ и модерация | Next.js | разделы `OS` и `AD` |
| База, авторизация, файлы | Supabase (Postgres, Row Level Security, Storage, Realtime) | модель данных из `architecture.md` |
| Вход | SMS-код по номеру телефона | заменяет аккаунты claude.ai |
| Пуши | Expo Notifications | события из функции `notifs()` |
| Оплаты | Kaspi или другой эквайринг | коллекция `orders` |
| Пересказ чатов | Claude API на сервере | функция пересказа из `06-actions.js` |

## Порядок переноса

1. Схема Postgres по таблице коллекций, политики RLS: житель видит данные только своего ЖК, пишет только свои записи, председатель управляет ЖК, где у него роль `osi`, модератор — всем. Личные сообщения читают только участники диалога.
2. Перенос справочника из `data/seed/` и, при необходимости, данных пилота из выгрузки модерации (выгрузку с личными данными не хранить в репозитории).
3. Проверка кода подъезда и лимит попыток в серверной функции, а не в приложении.
4. Приложение жителя на Expo: сначала вход, главная, «Кто перекрыл», мастера, барахолка, опросы (релиз 1–2), затем ОСИ и остальные сервисы.
5. Кабинет ОСИ и модерация на Next.js.
6. Пуши, SMS, оплаты, затем интеграции с домофонами и камерами.
