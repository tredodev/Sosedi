# Устройство и модель данных

## Как работает интерфейс

Приложение написано без фреймворка. Каждый экран жителя — функция в объекте `S`, которая по данным возвращает HTML-строку. Шторки снизу лежат в `SHEETS`, разделы кабинета ОСИ в `OS`, разделы модерации в `AD`. Все нажатия обрабатывает один делегированный обработчик: атрибут `data-go` ведёт на экран, `data-act` вызывает функцию из объекта `A`.

Состояние разделено на три части. `D` хранит данные из базы: подписки (`onSnapshot`) складывают туда коллекции и вызывают перерисовку. `F` хранит ввод текущей формы; поля связаны с ним через `data-f`, поэтому перерисовка при новых данных не стирает набранный текст. `NAVS` хранит стек экранов. Перерисовка (`R()`) объединяется через `requestAnimationFrame` и сохраняет фокус, позицию курсора и прокрутку.

Весь пользовательский текст выводится через `esc()`. Это обязательно для любого нового экрана: иначе появится XSS.

Запись в базу всегда идёт через `W(fn, сообщение)`. Обёртка показывает понятную ошибку и возвращает `false`, если запись не прошла. Если после записи экран зависит от только что созданного документа, нужно дождаться его в подписке через `until(() => ...)`, иначе роутер успеет перенаправить пользователя раньше.

## Платформа claude.ai

| Возможность | Для чего |
| --- | --- |
| `db` | общая база документов с подписками в реальном времени |
| `user` | идентификатор пользователя и проверка прав (`canEdit` = модератор) |
| `assets` | загрузка фото, отдача по адресу `/_blob/<id>` |
| `downloads` | протоколы голосований, листовки с кодами, записка на лобовое, выгрузка JSON |
| `sample` | пересказ пропущенных сообщений в чате и заполнение объявления по фото (модель уровня `quick`, `images: true`) |

Идентификаторы документов могут содержать только латиницу, цифры и символы `_ - . ~ : @ +`. Кириллицу в адреса документов не подставлять: её нужно переводить через `slug()` или отпечаток `sha()`.

## Модель данных

### Верхний уровень

| Путь | Что хранит | Кто пишет |
| --- | --- | --- |
| `zk/{zkId}` | ЖК: `guardOn`, `staff{отпечаток кода: {role, sup}}`, `directory[]`, `cityId`, `city`, `name`, `address`, `developer`, `houses[]`, `entrances`, `aptsPerEntrance`, `threshold`, `status` (`active`, `waitlist`, `catalog`), `codes{ключ: {hash, at}}`, `zones[]`, `payInfo`, `totalArea`, `leaguePrize`, `warranty` | модератор, председатель ОСИ |
| `waitlist/{uid}_{ключ}` | заявка в лист ожидания: `zkId` или свободное `name`, `cityId`, `city`, `street`, `ent`, `apt` | житель |
| `platform/settings` | тарифы поднятий, реквизиты Тредо, сборы, партнёр недели, настройки лавки | только модератор |
| `public/zk-{zkId}` | витрина ЖК: оценки, решённые заявки, цитата | председатель ОСИ; читать может любой |
| `votes/{uid}` | голоса в опросах соседей: `{postId: номерВарианта}` | только сам житель |
| `ovotes/{uid}` | голоса в официальных голосованиях: `{ballotId: {c, at, area, apt, zk}}` | только сам житель |
| `acks/{uid}` | участие и отметки: `n_<новость>`, `out_<отключение>` («воды нет»), `gb_<покупка>`, `cr_<сбор>` (сумма), `ev_<событие>` | только сам житель |
| `data/users/{uid}/me` | личное: выбранный ЖК, настройки уведомлений и тихие часы (`ntf`), прочитанные чаты, избранное, напоминания, паспорт квартиры, новоселье, коды подъездов председателя | только сам житель |

Счётчики («сколько отметили», «сколько участвует», «сколько обещали») считаются по документам `acks`, `votes`, `ovotes`, а не хранятся числом. Так два человека, нажавшие одновременно, не затирают друг друга.

## Подтверждение адреса

Председатель выпускает шестизначные коды на каждый подъезд (а если в ЖК несколько домов, то на каждую пару «дом-подъезд», ключ `<дом>-<подъезд>`). В документ ЖК пишется только отпечаток `sha256(zkId:ключ:код)`, сами коды видит только председатель в своих личных данных и в листовках. После трёх неверных попыток ввод блокируется на 10 минут на стороне интерфейса. Второй способ — ссылка-приглашение от уже подтверждённого соседа.
